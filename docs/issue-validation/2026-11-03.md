## API-driven auth guard — no session polling (2026-11-03)

- Removed the 15-second cookie-session timer and focus/visibility checks. Main bootstrap no longer installs a browser-session watcher; identity observer also no longer retries on focus.
- Existing local credentials skip cookie discovery and are validated by actual protected API requests. For a site without local credentials, one initial cookie discovery remains for CTSV SSO. A 403 from this optional discovery grants no session and falls back to explicit login, without retrying or changing the production origin allow-list.
- Explicit login accepts the authenticated token response and no longer requires a second cookie GET that could reject a valid login with 403. Server identity validation after accepting credentials remains.
- Refresh is demand-driven by a rejected API call. Authoritative refresh rejection/no refresh credential or confirmed identity rejection expires the local session. Resource 403, network failures and server errors do not become session-expired signals.
- Both roots mount an accessible auth guard with a session-expired modal and a required “Đăng nhập lại” action. Expiry suppresses automatic redirect and further protected requests until acknowledgement/login; manual logout behavior remains separate.
- Added regressions for no idle/focus/visibility polling, existing-session bootstrap, cookie-discovery 403, login without a probe, next-request expiry, one signal for concurrent failures and retention on permission/server failures.
- Current executor/browser are unavailable. Local execution and real-account live verification cannot be claimed.
